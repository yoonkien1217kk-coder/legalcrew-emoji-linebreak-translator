# LegalCrew Slack 워크스페이스 이모지 번역 앱 설계

## 목표

LegalCrew 워크스페이스 사용자가 채널 메시지의 `⋯` 메뉴에서 `SNS용 이모지 변환`을 선택하면, 별도 웹사이트로 이동하지 않고 Slack 안에서 브라우저·SNS에 붙여넣을 수 있는 유니코드 결과를 얻는다. 결과에는 `□`, `�` 또는 해석되지 않은 Slack 이미지 조각이 남지 않아야 한다.

## 확정된 사용자 흐름

1. 사용자가 Slack 메시지의 컨텍스트 메뉴에서 `SNS용 이모지 변환`을 선택한다.
2. 앱은 3초 안에 요청을 확인하고 복사용 모달을 먼저 연다.
3. 기본 Slack 별칭은 기존 1,975개 사전으로 즉시 유니코드 이모지로 바꾼다.
4. 처음 보는 커스텀 이모지는 이름과 이미지로 최대 3개의 유니코드 이모지를 추천한다.
5. 분석이 끝나면 같은 모달의 결과를 갱신한다.
6. 사용자는 결과 입력란을 선택해 복사한다. Slack Block Kit은 임의의 클립보드 쓰기 버튼을 제공하지 않으므로 데스크톱에서는 `Ctrl/Cmd+A`, `Ctrl/Cmd+C`, 모바일에서는 길게 눌러 복사한다.
7. 앱은 채널에 답글이나 변환 메시지를 게시하지 않는다.

## 변환 규칙

- 일반 문장, 공백, 줄바꿈은 유지한다.
- Slack 기본 이모지는 기존 `EMOJI_MAP` 값으로 변환한다.
- 커스텀 이모지는 캐시된 대응값이 있으면 그대로 사용한다.
- 캐시가 없으면 Slack `emoji.list`가 제공한 이름과 이미지 URL만 OpenAI Responses API에 보낸다. 원문 메시지와 작성자 정보는 보내지 않는다.
- AI 결과는 유니코드 이모지 1~3개만 허용한다.
- 신뢰도가 낮거나 API·이미지 처리에 실패하면 `:리자몽_화남:`을 `[리자몽 화남]`처럼 안전한 텍스트로 바꾼다.
- 커스텀 별칭에 한글 등 유니코드 문자와 `_`, `+`, `-`를 허용한다.
- 마지막 정리 단계에서 `□`와 `�`를 안전한 텍스트로 치환해 깨진 네모가 결과에 남지 않도록 한다.

## Slack 앱 구성

- 단일 LegalCrew 워크스페이스용 내부 앱이다. Slack Marketplace 배포는 하지 않는다.
- 메시지 단축어 callback ID는 `translate_sns_emoji`다.
- 필요한 bot scope는 `commands`, `emoji:read` 두 개뿐이다.
- `chat:write`, 채널 기록 읽기, 사용자 프로필 읽기 권한은 요청하지 않는다.
- 메시지 단축어 payload에 포함된 원문을 사용하므로 별도 채널 history 권한이 필요하지 않다.
- 모든 Slack 요청은 원본 요청 본문, 타임스탬프, Signing Secret으로 서명을 검증한다.
- 선택적으로 `SLACK_TEAM_ID`를 설정해 LegalCrew 외 워크스페이스 요청을 거부한다.

Slack 공식 문서상 메시지 단축어에는 `commands` 권한이 필요하고, payload에는 메시지 문맥이 포함된다. `emoji.list`는 `emoji:read` 권한으로 워크스페이스 커스텀 이모지 이름과 URL을 제공한다.

## 서버 구조

Node.js 20 이상에서 실행하는 작은 HTTP 서버로 만든다. Slack 및 OpenAI 호출은 내장 `fetch`를 사용하고, 애니메이션 GIF 첫 프레임을 PNG로 변환할 때만 `sharp`를 사용한다.

- `server/http-server.js`: `/health`와 `/slack/interactions` HTTP 경계
- `server/slack.js`: Slack 서명 검증과 Web API 호출
- `server/modal.js`: 로딩·결과 모달 payload 생성
- `server/custom-emoji.js`: 커스텀 목록 조회, 별칭 해석, OpenAI 분석, 결과 검증
- `server/mapping-store.js`: 분석 결과 JSON 저장과 원자적 갱신
- `server/interaction.js`: 메시지 단축어 처리 순서 조정
- `slack-app-manifest.yaml`: 관리자에게 전달할 최소 권한 앱 설정

서버는 먼저 HTTP 200으로 요청을 확인한 뒤 유효한 `trigger_id`로 모달을 연다. 이어서 해당 메시지에 실제로 등장한 미분석 커스텀 이모지만 병렬 분석하고 `views.update`로 모달을 갱신한다. 전체 워크스페이스 이미지를 한꺼번에 AI에 보내지 않는다.

## AI 분석과 캐시

- 기본 모델은 비용과 속도를 고려해 `gpt-6-luna`로 두고 `OPENAI_MODEL`로 교체 가능하게 한다.
- Responses API에 이름과 이미지 한 장을 입력하고 Structured Outputs로 `emoji`와 `confidence`를 받는다.
- 작은 글자 밈을 읽을 수 있도록 이미지 detail은 `high`를 사용한다.
- 애니메이션 GIF는 첫 프레임만 PNG로 변환한다. 첫 프레임 변환이 실패하면 이름만 분석한다.
- 결과는 `DATA_FILE` 경로의 JSON에 저장한다. 운영 환경에서는 영구 볼륨 경로를 설정한다.
- 같은 커스텀 이모지는 다시 AI에 보내지 않는다.
- 매핑 파일이 손상되면 빈 캐시로 복구하되 서버를 중단하지 않는다.

OpenAI 공식 문서상 Responses API는 이미지 입력과 구조화된 텍스트 출력을 지원하고, 최신 모델은 다국어 및 비전 입력을 지원한다.

## 오류 처리

- 서명 불일치, 5분 이상 지난 요청, 다른 팀 요청은 `401` 또는 `403`으로 거부한다.
- 지원하지 않는 interaction 유형은 `200`으로 확인만 하고 아무 작업도 하지 않는다.
- Slack 모달 열기 실패는 메시지 본문 없이 오류 코드만 기록한다.
- OpenAI 실패, JSON 불일치, 이모지 0개 또는 4개 이상 결과는 `[이름]` 폴백으로 처리한다.
- Slack 커스텀 별칭이 다른 커스텀 별칭을 가리키면 순환을 탐지하면서 실제 이미지 URL까지 따라간다.
- 최종 결과가 Slack 입력란 제한을 넘으면 안전하게 잘라 안내 문구를 붙인다.

## 개인정보와 로그

- Slack 메시지 원문, 사용자 ID, 커스텀 이미지 바이트를 로그에 남기지 않는다.
- OpenAI에는 미분석 커스텀 이모지의 이름과 이미지만 전달한다.
- Slack bot token, Signing Secret, OpenAI API key는 환경 변수로만 제공한다.
- 저장 파일에는 커스텀 이모지 이름, 선택된 유니코드, 신뢰도만 기록하며 이미지나 메시지 원문은 저장하지 않는다.

## 승인 및 배포 순서

1. 로컬에서 서버, 테스트, 앱 manifest를 완성한다.
2. 공개 HTTPS 주소에 서버를 배포한다.
3. 해당 URL을 반영한 manifest로 Slack 앱을 생성한다.
4. Slack Signing Secret과 bot token을 배포 환경에 등록한다.
5. LegalCrew 관리자에게 `commands`, `emoji:read` 두 권한의 설치 승인을 요청한다.
6. 승인 후 실제 채널 메시지로 단축어·모달·커스텀 이모지 분석을 검증한다.

관리자 계정에서의 앱 생성과 승인 클릭은 사용자가 수행해야 하며, 구현 결과물에는 복사 가능한 manifest와 정확한 설치 절차를 제공한다.

## 검증

- 기존 기본 이모지 회귀 테스트를 유지한다.
- 한글 커스텀 별칭과 네모 없는 폴백을 테스트한다.
- Slack 서명 정상·오류·만료를 테스트한다.
- 모달 payload가 원문과 줄바꿈을 보존하고 결과를 담는지 테스트한다.
- AI 결과의 1~3개 이모지 제한과 저신뢰 폴백을 테스트한다.
- 커스텀 별칭 체인과 순환을 테스트한다.
- 실제 네트워크 대신 주입한 `fetch` 경계로 Slack/OpenAI 요청 형식을 검증한다.
- 로컬 서버의 `/health`와 서명된 shortcut 요청을 통합 테스트한다.
